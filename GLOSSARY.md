# 📖 Master DevOps & Cloud Engineering Glossary

A standardized dictionary of foundational, architectural, and operational terms across the DevOps landscape.

---

## 🔤 Alphabetical Terminology Index

### A
* **Agent (Jenkins):** A worker node (machine or container) that connects to the Jenkins controller to execute pipeline build steps.
* **AMI (Amazon Machine Image):** A pre-configured template containing the operating system and installed software required to launch an EC2 instance.
* **Ansible:** An open-source, agentless configuration management and automation engine using YAML playbooks and SSH.
* **Artifact:** The deployable binary output generated by a build process (e.g. `.war`, `.jar`, `.tar.gz`, Docker image).
* **AWS S3 (Simple Storage Service):** Highly scalable, durable object storage service accessed via HTTP REST APIs.

### B
* **Blue/Green Deployment:** A zero-downtime release technique utilizing two identical environments (`Blue` = current production, `Green` = staging). Once verified, traffic switches instantaneously to Green.
* **Build Number (`$BUILD_NUMBER`):** A monotonically increasing integer assigned to each execution of a Jenkins job.

### C
* **Canary Deployment:** A deployment strategy where new code is released to a tiny fraction (e.g. 5%) of production users before rolling out globally.
* **CI (Continuous Integration):** The automated practice of frequently merging code changes into a central repository, followed by automated compiling, testing, and quality analysis.
* **CD (Continuous Delivery):** The practice of automating code progression up to staging environments, producing ready-to-release artifacts awaiting manual deployment approval.
* **CD (Continuous Deployment):** The practice of deploying every change that passes automated test stages straight into production with zero human intervention.
* **Clean as You Code:** SonarQube's methodology of enforcing Quality Gate standards strictly on newly written or modified code.
* **Controller (Jenkins):** The master orchestrator instance responsible for scheduling jobs, hosting plugins, storing configurations, and rendering the web UI.

### D
* **Declarative Pipeline:** A modern, structured syntax for defining Jenkins pipelines using the `pipeline {}` root block.
* **Docker:** An open-source containerization platform that packages applications and dependencies into isolated container runtimes.
* **Dockerfile:** A text file containing sequential instructions to build a Docker image.
* **DORA Metrics:** The four key DevOps performance indicators: Deployment Frequency, Lead Time for Changes, Mean Time to Recovery, and Change Failure Rate.

### E
* **EBS (Elastic Block Store):** High-performance persistent block storage volumes attached to Amazon EC2 instances.
* **EC2 (Elastic Compute Cloud):** On-demand scalable virtual compute servers provided by AWS.
* **etcd:** A consistent and highly-available distributed key-value store used as Kubernetes' storage for all cluster state.

### F
* **Fail-Fast Principle:** Designing automated systems to abort immediately upon detecting a failure, preventing defective code from propagating downstream.
* **Fork:** In Linux, a system call that creates an exact copy of the calling process.
* **Freestyle Project:** A Jenkins build job configured through the graphical web interface.

### G
* **GAV Coordinates:** Maven's unique three-part address for software packages: **G**roupId, **A**rtifactId, **V**ersion.
* **Git:** A distributed version control system for tracking changes in source code.
* **Groovy:** The dynamic, object-oriented language that powers Jenkins Pipeline scripts.
* **Group Repository:** In Sonatype Nexus, an aggregate virtual endpoint combining multiple hosted and proxy repositories under a single URL (e.g. `maven-public`).

### H
* **Hosted Repository:** In Sonatype Nexus, a repository physically stored on the local server used to host internal company artifacts (`maven-releases`, `maven-snapshots`).
* **HCL (HashiCorp Configuration Language):** The declarative configuration language used by Terraform.

### I
* **Idempotency:** An operation property where executing an action multiple times produces the exact same result as executing it once (a core principle of Ansible and Terraform).
* **IaC (Infrastructure as Code):** Managing and provisioning computing infrastructure through machine-readable definition files rather than manual ClickOps.
* **IAM (Identity & Access Management):** AWS service governing user authentication, permissions, and roles.
* **Inode:** A data structure on a Linux filesystem that stores metadata about a file or directory (ownership, permissions, disk block pointers), excluding its filename.

### J
* **JAVA_HOME:** An environment variable pointing to the root installation directory of the Java Development Kit (JDK).
* **Jenkins:** An open-source automation server designed to orchestrate CI/CD pipelines.
* **Jenkinsfile:** A text file checked into Git that contains the complete definition of a Jenkins pipeline.

### K
* **Kubernetes (K8s):** An open-source container orchestration platform for automated deployment, scaling, and operations of application containers.
* **Kubelet:** The primary node agent in Kubernetes that ensures containers described in PodSpecs are running and healthy.

### M
* **Maven:** An Apache build automation and dependency management tool primarily used for Java applications.
* **Multi-Stage Build:** A Dockerfile optimization pattern using multiple `FROM` instructions to compile code in a heavy image and copy only the final binary into a lightweight runtime image.

### N
* **Nexus OSS:** An enterprise artifact repository manager developed by Sonatype.
* **Nginx:** A high-performance HTTP web server and reverse proxy.

### P
* **Pipeline as Code:** Managing delivery pipeline configurations within source control repositories.
* **Pod:** The smallest deployable computing unit in Kubernetes, containing one or more tightly-coupled containers sharing storage and network namespaces.
* **POM (Project Object Model):** The fundamental configuration unit in Maven, defined in `pom.xml`.
* **Proxy Repository:** In Nexus, a local caching repository that mirrors a public upstream repository (e.g. Maven Central).

### Q
* **Quality Gate:** A set of Boolean conditions in SonarQube (e.g. 80% coverage, 0 blocker bugs) used to determine if code meets release criteria.

### R
* **Reverse Proxy:** An intermediate proxy server that sits in front of backend servers, forwarding incoming client requests to preserve backend security and terminate SSL/TLS.
* **Rollback:** The operational procedure of reverting a deployed system to its previous known-good working state.

### S
* **Security Group:** A virtual, stateful firewall attached to AWS EC2 instances controlling inbound and outbound traffic.
* **SG-to-SG Rule:** A security group rule that allows traffic from another security group ID rather than an IP CIDR block.
* **SonarQube:** An automatic static code analysis platform that inspects code for bugs, vulnerabilities, and code smells.
* **Systemd:** The primary Linux init system and service manager responsible for controlling background daemons.

### T
* **Terraform:** An open-source Infrastructure as Code tool created by HashiCorp for cloud provisioning.
* **Trunk-Based Development:** A branching strategy where all developers merge short-lived branches frequently into a single shared branch ("trunk").

### W
* **Webhook:** An HTTP POST callback event sent by a source system (like GitHub or SonarQube) to notify a destination server (like Jenkins) that an action has finished.
* **Workspace (Jenkins):** The dedicated working directory on disk where Jenkins checks out source code and performs build commands.
