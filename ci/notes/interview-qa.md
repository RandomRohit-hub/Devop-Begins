# 🎯 CI/CD & Jenkins Interview Questions & Answers

A curated question-and-answer guide based on foundational DevOps CI/CD pipeline concepts, Jenkins tool configuration, and artifact management.

---

### Q1: What is Continuous Integration (CI) and what is its primary objective?
> **Answer:** Continuous Integration is a software development practice where developers frequently merge code changes into a central repository, after which automated builds and tests are run. Its primary objective is to detect integration bugs early (**Fail-Fast Principle**), improve software quality, and reduce the time required to validate and release updates.

---

### Q2: What are the 5 core stages of a standard CI pipeline?
> **Answer:** Remember the mnemonic **F ➔ B ➔ T ➔ A ➔ U**:
> 1. **F - Fetch Code:** Checkout latest commits from GitHub.
> 2. **B - Build:** Compile source code and resolve dependencies using Maven.
> 3. **T - Test:** Run unit tests via Maven Surefire plugin.
> 4. **A - Analyze:** Perform static code analysis and Quality Gate checks with SonarQube.
> 5. **U - Upload:** Store packaged, versioned binaries in an artifact repository (Nexus OSS / AWS S3).

---

### Q3: Why do we configure tools under "Manage Jenkins ➔ Tools"?
> **Answer:** Jenkins needs to know the exact path and version of build runtimes (such as JDK 17, Maven 3.9, Git, NodeJS) installed on the system. Configuring them in Tools allows different jobs to specify their own required runtimes (e.g., Job A requires JDK 11 while Job B requires JDK 17) in an isolated, standardized manner.

---

### Q4: What is `JAVA_HOME` and what is a common mistake when setting it?
> **Answer:** `JAVA_HOME` is an environment variable that points to the top-level directory where the Java Development Kit (JDK) is installed (e.g. `/usr/lib/jvm/java-17-openjdk-amd64`).  
> A common mistake is pointing to `/usr/bin/java` (which is a symlink to the binary) or `/usr/local/jvm` (which may not exist), causing Jenkins to error with *"`...doesn't look like a JDK directory`"*. `JAVA_HOME` must contain the `bin/`, `lib/`, and runtime directories.

### Q5: What is the difference between Unit Testing and SonarQube Analysis?
> **Answer:**
> * **Unit Testing (`mvn test`):** Tests **functional correctness** dynamically during execution. Validates whether functions output expected results for given inputs.
> * **SonarQube Analysis:** Tests **static code quality, security, and maintainability** without running the code. Identifies code smells, security vulnerabilities, bugs, duplicated lines, and evaluates Quality Gate compliance.

---

### Q6: What is a Quality Gate in SonarQube?
> **Answer:** A Quality Gate is a set of measure-based Boolean conditions that a project must pass before it can be qualified for release (e.g., code coverage > 80%, zero new critical vulnerabilities, duplication < 3%). If the Quality Gate fails, Jenkins can abort the build immediately.

---

### Q7: Why should we store artifacts in Nexus or S3 rather than keeping them in the Jenkins workspace?
> **Answer:**
> 1. **Durability & Resilience:** Workspaces can be cleared or wiped automatically during checkout. S3 provides 99.999999999% durability.
> 2. **Disk Capacity:** Continuous builds producing 100MB+ WAR files quickly exhaust the Jenkins controller's hard disk space.
> 3. **Decoupled Deployments:** CD pipelines and staging/production servers can securely download artifacts without requiring access to the Jenkins controller.

---

### Q8: How does artifact versioning enable instant production rollbacks?
> **Answer:** By copying each build output into a unique versioned file name (e.g. `cp target/vprofile-v2.war versions/vpro$BUILD_NUMBER.war`), every build artifact is preserved. If Build #3 introduces a critical bug in production, operations teams can immediately deploy `vpro2.war` from S3 or Nexus without needing to re-check out and re-compile older source code under high-stress outage conditions.

---

### Q9: Where are the initial administrator password and home directory located in Jenkins?
> **Answer:**
> * **Home Directory:** `/var/lib/jenkins/`
> * **Initial Password:** `/var/lib/jenkins/secrets/initialAdminPassword`
> * **Default HTTP Port:** `8080`

---

### Q10: What is the difference between `$BUILD_NUMBER` and a custom `$VERSION` variable?
> **Answer:**
> * `$BUILD_NUMBER` is an automatic, sequentially incrementing integer (`1`, `2`, `3`) generated by Jenkins for each build run.
> * `$VERSION` is a custom user-defined parameter or pipeline variable allowing semantic release versioning (such as `2.3.6` or `1.0.0-RELEASE`).
